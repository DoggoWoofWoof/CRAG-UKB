# `results/` — Pipeline Output Files

Contains the JSON output from each pipeline run and the final aggregated comparison CSV. All files are auto-generated by `src/router/factory.py` and `src/evaluation/metrics.py` — do not edit manually.

---

## File Naming Convention

```
results/
├── vector.json              → VectorRAG output (400 queries)
├── graph.json               → GraphRAG output (400 queries)
├── crag_standard.json       → CRAGStandard output (400 queries)
├── crag_colbert.json        → CRAGColBERT output (400 queries)
├── crag_agent.json          → CRAGAgent v4 output (400 queries)
└── benchmark_comparison.csv → Final P@1, R@10, MRR summary table
```

---

## Per-Query JSON Schema

Every JSON file contains a list of 400 objects with this schema:

```json
{
  "id": 42,
  "query": "Who is the CEO of the company that acquired GitHub in 2018?",
  "category": "Multi-hop",
  "target_system_advantaged": "Graph-RAG",
  "generated_answer": "Satya Nadella",
  "retrieved_nodes": ["node_Microsoft_2847", "node_GitHub_Acquisition_2018"],
  "reasoning_path": ["node_GitHub_1102", "node_Microsoft_2847", "node_CEO_Nadella"],
  "latency_seconds": 0.41,
  "metadata": {
    "strategy": "graph",
    "partitions_selected": null,
    "colbert_scores": null
  }
}
```

The `reasoning_path` field is only populated by `crag_agent.py`. Flat retrievers return an empty list.

---

## Final Comparison Table Schema (`benchmark_comparison.csv`)

| Column | Description |
|---|---|
| `category` | One of: Semantic, Multi-hop, Fallback/Web, Exact Lexical, Routing |
| `strategy` | One of: vector, graph, crag_standard, crag_colbert, crag_agent |
| `P_at_1` | Precision@1: was the top node correct? |
| `R_at_10` | Recall@10: were all expected nodes in top-10? |
| `MRR` | Mean Reciprocal Rank |
| `avg_latency_s` | Average query latency in seconds |
| `n_queries` | Number of queries in this category (always 80) |
